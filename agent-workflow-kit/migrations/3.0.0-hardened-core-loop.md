# Migration 3.0.0-hardened-core-loop

**From:** versions < 3.0.0   **To:** 3.0.0

## Why

3.0.0 replaces the recorded review-loop machinery (review-ledger / fold-completeness /
verification-profile) with a COMPUTED core: red-proof custody + changed-line coverage inside
`run-gates --final`, ship-class review receipts with self-declared probe AND posture markers,
and an optional pre-commit guard that binds a commit to the latest green final-run receipt.
The retired tools no longer exist; a declaration or receipt that references them stops working
loudly, never silently.

## Steps

1. **Node floor:** ensure Node **>= 22** (the built-in lcov reporter the loop consumes).
2. **Gates declaration:** the upgrade's `gates-migration` step runs the migration with no question —
   `node <installed-kit>/references/scripts/gates/migrate-gates.mjs --kit-tools <installed-kit>/tools --cwd <project> --apply`.
   It removes a retired ledger/fold gate whose target is proven absent, moves the canonical
   `unit-tests` cmd onto the stable kit command, moves a declared `coverage-check` gate LAST, and
   cleans retired git-dir stores; it adds the canonical checker only on the user's yes, through
   its printed `--apply --add-checker` line. CUSTOMIZED entries are reported with a paste-ready
   recovery — resolve them by hand.
3. **Review receipts:** receipts minted by pre-3.0.0/4.0.0 bridge wrappers carry no `posture`
   field and STOP satisfying the review-state gate (fail-closed, the probe-marker precedent).
   Refresh the placed bridges (init/upgrade does this), then re-run the required reviews.
4. **Commit guard (optional, consented):** once the declaration is final-run-capable, the
   advisor's `commit-guard` item arms the pre-commit hook: the agent applies it on the user's yes
   after its check, by the consent route of the Recommendations mode, and the apply reads the hook
   back to verify the arm took. A 2.x deployment's project-local `scripts/install-git-hooks.mjs`
   predates the arm: an unarmed hook after the installer's exit 0 makes the apply exit 6 with
   one line naming the hook and the guard line the installer left out, ending with the upgrade
   route — `/agent-workflow-kit upgrade` writes the kit's current installer over it with no
   question — and the item returns at the next run.
5. **Re-stamp:** init/upgrade re-stamps `docs/ai/.workflow-version` to 3.0.0.

## Verification

`node <installed-kit>/tools/run-gates.mjs --final` exits 0 and records a green receipt;
`node <installed-kit>/tools/review-state.mjs --check` names any remaining obligation.
