# Migration 1.2.0-agent-attribution

**From:** versions < 1.2.0   **To:** 1.2.0

## Why

1.2.0 makes **agent attribution opt-in**. The agent may attribute work to itself / AI —
`Co-Authored-By` trailers, "Generated with …" footers, AI/agent/model mentions in code,
comments, commit messages, PR titles/bodies, branch names, or docs — **only if the user
allows it**. Default is `off`. The choice is recorded in an *Attribution* block in the
project's `AGENTS.md`; pre-1.2.0 deployments have no such block.

A single `Co-Authored-By` trailer is enough to list an AI as a repo contributor, and GitHub
keeps it permanently via PR refs — so the safe default is "no mention anywhere".

## Steps

1. Open the project's entry point `AGENTS.md` (the real file; `CLAUDE.md` is a symlink to it).
2. **Idempotency check** — if it already contains a `## ✍️ Attribution` heading, skip step 4;
   step 5 still applies.
3. **Ask only for a missing block's answer not already collected**: may the agent attribute work
   to itself / AI anywhere (commits, PRs, code, comments, docs)? **Default to `off`** unless opted in.
4. Preview with `node ${CLAUDE_SKILL_DIR}/tools/migration-blocks.mjs --cwd <project>`; it writes nothing.
   Re-run that command with `--apply --attribution <off|on>` to insert from the kit's template.
   If the Communication language block is absent too, collect its answer and pass `--language <answer>`
   in the same run: the writer places both blocks in ONE atomic write, or withholds with
   `answer-missing` and writes nothing if an answer is missing.
   Upgrade step 7 runs this same command with the answers its step-6 prompt collected; never re-ask them.
   Relay the writer's lines; a named refusal on stderr stops the migration and is relayed as worded.
   For `answer-missing`, ask exactly the missing answers and retry `--apply` once; a second withheld run stops.
5. **Whenever the Attribution block reads `off`**, whether just inserted or already present,
   the harness setting stays outside the writer: for Claude Code it is the advisor's `attribution`
   item, which the agent applies on the user's yes after its check, so the automatic trailer stops
   (a doc directive cannot stop a harness-added trailer). It sets `attribution` to
   `{"commit":"","pr":"","sessionUrl":false}` in the project's `.claude/settings.json`, every other
   key kept. An existing "includeCoAuthoredBy": false already converges the item unless an
   "attribution" key sets a commit or PR text.
   - For other tools, disable their equivalent co-author / footer setting if present.
6. The writer refuses with `cap` rather than push `AGENTS.md` past its 100-line budget;
   trim the entry point and re-run the upgrade. Do **not**
   retroactively rewrite existing git history here — that is a separate, deliberate operation.

## Verification

- `AGENTS.md` has exactly one `## ✍️ Attribution` block, with `off` or `on` (no leftover
  `{{AGENT_ATTRIBUTION}}` placeholder).
- If `off` + Claude Code: the advisor renders no `attribution` item, and `.claude/settings.json`
  is valid JSON (`node -e "JSON.parse(require('fs').readFileSync('.claude/settings.json'))"`).
- The docs cap-validator is still green (`node scripts/check-docs-size.mjs` for Node projects).

## Rollback

Delete the inserted `## ✍️ Attribution` block (and its trailing `---`) from `AGENTS.md`, and
remove the `attribution` key from `.claude/settings.json` if the `attribution` item wrote it. No
other files were changed.
